**************** Sobre generic views do DRF


APIView é a forma mais genérica de view de uma API. Ela te dá total liberdade: você escreve o `get`, o `post`, o `put` e o `delete` na mão, do jeito que quiser 3. Ela não traz os métodos prontos — a ideia é justamente "faz do jeito que você quiser, se vira" . Você importa com `from rest_framework import views` e herda de `views.APIView` 3.

Generic views são o oposto em termos de conveniência. Elas já vêm com as operações do CRUD implementadas, uma para cada tipo: `CreateAPIView` (só cria, método post), `ListAPIView` (lista, get), `RetrieveAPIView` (detalhe, get), `DestroyAPIView` (delete) e `UpdateAPIView` (patch e put) 1. Você importa com `from rest_framework import generics` .

E tem um detalhe bacana: o DRF também traz versões que mesclam essas operações, para você ter menos endpoints. A `ListCreateAPIView`, por exemplo, já faz list e create no mesmo endpoint, com o get e o post prontos . E a `RetrieveUpdateDestroyAPIView` faz retrieve, update e destroy de uma vez 6.

Resumindo a diferença de espírito: a APIView te entrega o controle total e nada pronto; as generics fazem o trabalho por você — você só diz qual model e qual serializer usar .

# opções do choice pra ser usado no campo nationality...
NATIONALITY_CHOICES = (
    ('USA', 'Estados Unidos'),
    ('BRAZIL', 'Brasil')
)

class Actor(models.Model):
    name = models.CharField(max_length=200)
    birthday = models.DateField(blank=True, null=True)
    nationality = models.CharField(max_length=100, blank=True, null=True,
                                   choices=NATIONALITY_CHOICES)
    
    def __str__(self):
        return self.name

crie o models dele...

from django.db import models
from actors.models import Actor
from genres.models import Genre


class Movie(models.Model):
    title = models.CharField(max_length=500)
    genre = models.ForeignKey(Genre, on_delete=models.PROTECT,
                               related_name='movies')
    release_date = models.DateField(null=True, blank=True)
    actors = models.ManyToManyField(Actor, related_name='movies')
    resume = models.TextField(blank=True, null=True)
    
    def __str__(self):
        return self.title

crie o app reviews e registre no settings...


no models dele...


from django.db import models
from django.core.validators import MinValueValidator, MaxValueValidator
from movies.models import Movie


class Review(models.Model):
    movie = models.ForeignKey(Movie, on_delete=models.PROTECT,
                              related_name='reviews')
    stars = models.IntegerField(
        validators=[
            MinValueValidator(0, 'Avaliação não pode ser inferior a 0 estreals.'),
            MaxValueValidator(5, 'Avaliação não pode ser superior a 5 estrelas.'),
        ]
    )
    comment = models.TextField(null=True, blank=True)
    
    
    def __str__(self):
        return self.movie

Versionamento de URLs e recursos

como boa prática de um projeto django cada app do nosso projeto terá um arquivo urls.py com suas devidas urls e dentro da url raiz vai estar apontando para o arquivo de url de cada app.
no nosso caso essa parte já foi feita.



como ficaria o arquivo de url de cada app...



from django.urls import path
from movies.views import MovieCreateListView, MovieRetrieveUpdateDestroyView


urlpatterns = [
    path('movies/', MovieCreateListView.as_view(), name='movie-create-list'),
    path('movies/<int:pk>/', MovieRetrieveUpdateDestroyView.as_view(), name='movie-detail-view'),
]


agora como ficaria o url raiz e com o versionamento que serve para quando for lançada uma versão nova da api, a antiga vai continuar funcionando sem quebrar...



from django.contrib import admin
from django.urls import path, include


urlpatterns = [
    path('admin/', admin.site.urls),
    path('api/v1/', include('genres.urls')),
    path('api/v1/', include('actors.urls')),
    path('api/v1/', include('movies.urls')),
    path('api/v1/', include('reviews.urls')),
   ]


agora pra acessar os recursos (url) da api tem que colocar o prefixo, ou seja api/v1 mais o restante da url por exemple http://127.0.0.1:8000/api/v1/reviews/
ou http://127.0.0.1:8000/api/v1/reviews/1/ se for o caso...


e se for fazer modificações significativas na api pode-se criar uma nova versão...

crie um novo arquivo de urls no app tipo urls_v2.py e nele coloque as urls que desejar...


na url raiz faça um novo include apontando para o novo arquivo de url...

 path('api/v2/', include('reviews.urls_v2.py')),
